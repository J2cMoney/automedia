---
name: fast-patch
description: 当 workflow-router 判定为 Fast Patch，或用户要求小修、小 bug、文案、样式、局部 UI 修复、单文件局部改动时使用。快速修改并做最小必要验证。
---

[任务]
    快速处理低风险局部修改。目标是少读、少问、少跑重流程，但必须保护已有功能。

[依赖检测]
    必需：用户请求、相关项目代码。
    可选：相关测试、现有样式/组件、运行脚本。缺失时降级为静态检查和明确说明未验证项。

[文件结构]
    fast-patch/
    └── SKILL.md  # 本文件，无 references / templates

[第一性原则]
    小修小做：只读与本次问题直接相关的文件和引用点，不扫描全项目文档。
    不碰流水线：不更新 Product-Spec.md、不更新 DEV-PLAN.md、不派 code-reviewer、不自动 commit、不自动 push。
    最小验证：跑能证明这次改动的最小命令；没有命令就做静态核对并说明。
    风险升级：发现改动涉及需求、跨模块、数据、权限、支付、发布、安全时，停止 fast-patch，交回 workflow-router 升级判档。

[适用边界]
    可做：改文字、改颜色/间距、小 CSS、修明显 typo、修单点报错、调整单个组件局部行为、补一个小条件判断。
    不做：新增完整功能、改 API 契约、改数据库、改登录权限、改支付、改发布配置、批量重构、跨多模块架构调整。

[工作流程]
    1. 确认是 Fast Patch，并写 .codex/workflow-mode 为 fast。
    2. 定位相关文件，必要时 grep 引用点。只读本次必要上下文。
    3. 改动前用一句话说明影响范围。
    4. 做最小修改，不顺手重构。
    5. 跑最小必要验证：优先相关单测、typecheck、lint、局部页面预览或复现步骤回归。
    6. 汇报改动、验证结果、未验证项。用户没要求时不 commit。

[验证选择]
    文案/样式：静态核对 + 如有前端页面则启动或截图检查关键位置。
    小 bug：复现失败 → 修改 → 同步骤复现通过。
    TypeScript：优先跑相关测试；没有测试时跑 `tsc --noEmit` 或项目既有 typecheck。
    配置小改：跑读取该配置的最小命令。

[输出风格]
    简短直接。说明“按 Fast Patch 快修处理”，然后给改动和验证。不要讲完整产品流程。

[初始化]
    执行 [依赖检测]。
